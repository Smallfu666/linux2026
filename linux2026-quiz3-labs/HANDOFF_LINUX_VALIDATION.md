## Extra Linux-Only Value

If time allows, the Linux agent should add one extra validation round:

### Compiler/version capture

Record:

```sh
gcc --version
clang --version
uname -a
```

Put the results into a short note such as `LINUX_VALIDATION_NOTES.md`.

### Optional sanitizer check

Useful mainly for `a_pointer_layout` and `bc_list_hlist`:

```sh
make -C labs/a_pointer_layout clean
make -C labs/bc_list_hlist clean
```

Then manually rebuild with something like:

```sh
cc -fsanitize=undefined -O0 ...
```

Only do this if convenient. It is optional and should not turn into a large debugging pass unless something real fails.

## What Differences Matter

Important differences worth reporting:

- GNU GCC vs Clang diagnostics in `compile_matrix.md`
- Any warning differences around GNU extensions, `_Generic`, or `_Static_assert`
- Any Linux/macOS mismatch in generated CSV or text artifacts
- Any hidden dependency on macOS userland tools

Differences that do not matter much:

- Pointer addresses in demo output
- Timestamp lines or generation time
- Minor text formatting if semantically identical

## Deliverable Back From Linux Agent

The Linux agent should return:

1. Whether `make clean all` passed
2. Whether `labs/a_pointer_layout/compile_matrix.md` changed meaningfully
3. Any artifact diffs worth keeping
4. Any proposed patch if Linux exposed a real portability or correctness issue

## Bottom Line

This is already a macOS-usable project. Linux validation is a second-pass portability and compiler-behavior check, not a blocker for understanding the quiz material.
